# PROJECT: Personal Growth AI OS (MVP)

You are a senior staff engineer and AI systems architect.

Help me build an MVP of a Personal AI Operating System that coordinates my learning, projects, career, content creation, small business opportunities, and evidence from my real development work.

IMPORTANT: This is an MVP for ONE USER ONLY. Do NOT over-engineer, introduce microservices, Kubernetes, complex distributed systems, or unnecessary infrastructure.

Before writing implementation code, first analyze the requirements and create a practical architecture and implementation plan.

---

# CORE PRODUCT VISION

The application is a personal AI operating system where multiple specialized agents work together.

The key principle is:

MY LEARNING → MY PROJECTS → MY PROOF OF WORK → MY JOB PROFILE → MY CONTENT → MY BUSINESS OPPORTUNITIES

These must NOT operate independently.

Every agent should share relevant context through a central database.

For example:

- If I learn RabbitMQ, Kubernetes, AI Agents, or System Design, the Project Agent should consider those skills when recommending projects.
- If I implement something in a project, the Career Agent should know that I have ACTUALLY implemented it.
- The Job Agent must only recommend jobs based primarily on skills I can prove through real projects or experience.
- The Content Agent should generate content ideas based on things I actually learned, built, struggled with, or solved.
- DSA practice should support my software engineering interview goals and pattern recognition weaknesses.
- Business opportunities should leverage technologies and skills I actually possess.
- Claude Code development activity should become evidence of actual work completed, not merely self-reported learning.

The system should build a continuously evolving "Proof of Skills" profile.

The system should feel like one connected intelligence system, NOT six separate chatbots.

AI usage must be controlled.

3. Avoid repeatedly analyzing identical data.

4. Add basic usage tracking.

Track:

model

## SESSION_START

Purpose:
Record that a development session has started.

- Git repository information

## FILE_ACTIVITY

Triggered when meaningful file modifications occur.

Do NOT create a database event for every individual keystroke.

Aggregate activity locally.

Capture:

- Files created
- Files modified
- Files deleted
- Project
- Timestamp

The collector should aggregate these events into a session.

## SESSION_CHECKPOINT

When Claude finishes a meaningful task or stops.

Capture:

- Current git diff summary
- Files changed
- Git status
- Recent commits if available

Do NOT upload full source code by default.

Only upload metadata and summarized evidence.

## SESSION_END

Finalize the development session.

Capture:

- Start timestamp
- End timestamp
- Duration
- Files changed
- Git commits
- Git diff statistics
- Project information

Create one consolidated RAW_ACTIVITY record.

# CODING RULES

1. TypeScript strict mode.
2. Keep modules independent.
3. Use dependency injection where appropriate.
4. Never expose API keys to client-side code.
5. Validate all external input.
6. Use structured AI outputs with Zod schemas.
7. Log agent failures.
8. Make agent runs idempotent where practical.
9. Keep functions small and testable.
10. Prefer simple code over clever abstractions.
11. Add comments only where logic is non-obvious.
12. Do not create abstractions for hypothetical future needs.
13. Do not let AI-generated claims automatically become skill proof without evidence rules.

# SUCCESS CRITERIA FOR MVP

The MVP is successful if I can:

1. Log my learning and DSA practice.
2. See AI analysis of my DSA pattern weaknesses.
3. Track skills from LEARNING → IMPLEMENTED → PROVEN.
4. Create projects and map features to skills.
5. Automatically capture meaningful development activity from Claude Code running on my Mac.
6. Store raw development activity safely even during temporary connectivity failures.
7. Analyze daily development activity and convert it into suggested evidence.
8. Analyze a manually entered job against REAL proof of skills.
9. Generate LinkedIn content ideas from actual learning/project work.
10. Get realistic small-business software ideas based on my skills.
11. See all agent activity in one dashboard.
12. Receive a daily prioritized briefing.
13. Approve or reject important AI recommendations.
14. Run entirely as a single-user application with minimal infrastructure cost.

The system should feel like one connected intelligence system, NOT six separate chatbots.

The unique core loop should be:

LEARN
  ↓
PRACTICE DSA + SYSTEM DESIGN
  ↓
BUILD PROJECT
  ↓
CAPTURE ACTUAL DEVELOPMENT ACTIVITY
  ↓
PROVE SKILLS
  ↓
MATCH BETTER JOBS
  ↓
CREATE REAL CONTENT
  ↓
IDENTIFY SMALL BUSINESS OPPORTUNITIES
  ↓
LEARN WHAT IS MISSING
  └──────────────→ LEARN AGAIN

Start with PHASE 0 only.

Do not write implementation code until the system design and MVP scope have been presented.
